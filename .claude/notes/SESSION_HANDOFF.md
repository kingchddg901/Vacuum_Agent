#### 🐞 TWO DEFECTS FOUND BY THAT RUN (both evidence-backed, NEITHER FIXED)
The first attempt **failed correctly** — the guard refused rather than cleaning wrong:
`zone settings did not take — refusing to clean with unconfirmed settings: water
(number.robin_wetness_level=None, wanted 16)`. Root cause: Chris picked **Mode=Vacuum + Water=Moist**,
a contradiction — `wetness_level` is `unavailable` unless the robot is in a MOP mode (and
`cleaning_route` only exposes `intensive`/`deep` in mop modes; in `sweeping` its options are just
`['quick','standard']`). Re-running with **Vac+Mop** worked immediately.
1. **CARD does not gate settings by MODE** (frontend). The zone dialog offered Water/Route values
   invalid for the chosen Mode. Fix = the settings-per-mode **gating tables** already specced in
   `.claude/notes/DESIGN-dreame-cleaning-mode-toggle.md` (both tables, read off the app) — listed
   there as NOT YET BUILT. This is the user-facing defect.
2. **PRECALL write ORDER is flat** (backend, `dispatch/manager.py::_dispatch_zone_with_global_precall`).
   It applies the plan with `for p in plan: await _apply(...)` in whatever order `gp["settings"]`
   lists. But **`cleaning_mode` GATES wetness/route** — it must be written FIRST and allowed to
   settle before the gated ones, or the write lands on an `unavailable` entity and the readback
   refuses. Card gating makes this much less reachable, but mode-first ordering would make the
   backend correct on its own.

## The composition model (design, not yet built)

Everything decomposes into small key spaces, which makes i18n mostly LIFTING rather than
translating - the manuals already carry 6-34 language editions of the same content at
computable offsets, with the language code printed on the page.

    interval:  [action] + [frequency] + [numeral] + [unit]
               ~6 actions, ~4 frequencies, integers (not keys), 4 units
               `repetition` is a TOKEN not a number, so "each_use" and "6-12" are
               ordinary values, not special cases
    procedure: a sequence of [action][object] pairs

⚠ MAKE THE KEY THE WHOLE PATTERN, not the word "every". Japanese puts it as a SUFFIX
(`6 ～ 12 カ月ごと`, `2 週間に一度`) so concatenating a prefix produces broken Japanese.

Validated against the nine authored families: `main_brush` reduces to ONE skeleton with
one node of difference (Group B has brush end-covers). `dustbin`'s six variants are one
skeleton plus two booleans (`has_robot_cover`, `has_dust_box_cover`). `washboard` looked
like it resisted composition and does NOT - Chris called that correctly; all four share
`exit station -> remove washboard -> [CLEAN] -> reinstall -> return robot` and only the
`[CLEAN]` sub-procedure varies, by hardware.
